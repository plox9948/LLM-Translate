# Задача: устранить декод-артефакты IndicTrans2 200M на уровне декодера

Ветка: `main` (ветка `indictrans` удалена без merge; этот файл самодостаточен).
Каталог `main` (v13) содержит пары `indictrans2-en-indic-int8` / `indictrans2-indic-en-int8` (200M) — задачу проверять именно на них.

## Контекст: причина артефактов (результат расследования)

Артефакты 200M — дублирование слова/фразы перед EOS: `नमस्कार , नमस्कार ।`, `स्वागत छ स्वागत छ ।`, `Hello , Hello .` (иссы #28, #30).

Первопричина — **дефект дистиллированных чекпоинтов `dist-200M`**, подтверждён апстримом:
- AI4Bharat/IndicTrans2 issue **#105** «Distilled Model Repeats Words…»: повторение возникает **только у dist-200M**, base-1B корректен на тех же входах; воспроизводится при fp16 **и beam=5** (beam=10 не лечит); ~0,1% фраз; **разбиение входных предложений на более короткие убирает эффект**; дистиллированный RoPE-вариант тоже повторяет.
- issue **#131** — в официальном движке нет repeat-guard'ов (просят expose CT2-опций).

Механизм: студент обучен на «сглаженных» soft-логинах учителя; на границе фразы EOS откалиброван плохо — «продолжить предыдущий блок» конкурирует с EOS, Marian-архитектура цепляет attention-петлю «повторить последний спан», greedy фиксирует ре-генерацию вместо EOS. У 1B (non-distilled) EOS-маржа резкая — артефактов нет.
Усиливают (не первопричина): чистый greedy у нас (апстрим везде beam_size=5: `inference/engine.py:182`, `huggingface_interface/example.py` `num_beams=5`) и динамическая int8 (сужает поля логитов).

Текущие `RepetitionTrimmer` + ретрай `no_repeat` (#28/#30/#62) только **прячут** артефакт в post-processing: RAW-декод остаётся циклическим, цикл съедает бюджет генерации и искажает остаток фразы (частичные падения chrF).

Цель задачи: подавить цикл **до детокенизации** — на уровне генерации.

## Изменение 1: маска `no_repeat_ngram=3` с первого прохода

Файл: `app/src/main/java/com/plox/llmtranslate/domain/runtime/IndicTransOnnxRuntime.kt`
(функция `translateSingleChunk`, ~473–519; `translateOnce` принимает `noRepeatNgramSize`).

Сейчас: проход 1 — чистый greedy (`noRepeatNgramSize = 0`), при вырождении — ретрай с `NO_REPEAT_NGRAM_SIZE = 3`.

Сделать **обмен проходов**:
- проход 1: `noRepeatNgramSize = NO_REPEAT_NGRAM_SIZE` (маска работает с первого токена — второй проход уже встречавшейся 3-граммы невозможен; `maskRepeatingNgrams` из `DecodeGuards.kt` уже НЕ маскирует EOS, т.е. завершение перевода не блокируется);
- проход 2 (ретрай, если первый вырожден): `noRepeatNgramSize = 0` — чистый greedy как фолбэк для легитимных 3-граммных повторов (маска их запрещает и портит вывод, например «no no no…» из входа);
- политика выбора победителя сохраняет текущую схему «первый не вырожден → он; иначе второй не вырожден → он; оба вырождены → лучший по `uniqueWordRatio`», с точкой схода по swapped-порядку.

Сопроводительные правки:
- KDoc `translateSingleChunk` / `translate` («decode → … ретрай …») — отразить новый порядок;
- комментарий `NO_REPEAT_NGRAM_SIZE` (строка ~73): маска теперь основного прохода, ретрай — без маски;
- абзац «Контракт подавления повторов (ревью #64)» в `GreedyDecoder.kt` и в `IndicTransOnnxRuntime.translateOnce` остаётся верен (штрафов в логитах по-прежнему нет — только жёсткая маска), но фразу о «первом чистом проходе» в KDoc `translateSingleChunk` обновить.

## Изменение 2: чанкинг строго по предложениям (без упаковки сегментов)

Файл: `app/src/main/java/com/plox/llmtranslate/domain/runtime/ChunkPlanner.kt`
(единственный пользователь — `IndicTransOnnxRuntime.translate`, стр. ~359; Marian режет предложения через `splitsIntoSentences` на уровне UI, на него изменение не влияет).

Сейчас `planChunks` режет вход `SentenceSplitter.splitWithSeparators` (границы `.`/`!`/`?`/`…`/данда `।`/`॥` — уже есть) и затем **жадно упаковывает** последовательные предложения в один чанк, пока влезает в бюджет 258 токенов: короткий многосоставный вход декодируется целиком.

Сделать **1 предложение = 1 чанк** (как в апстриме: `inference/engine.py` всегда сплитит предложения перед декодом; наблюдение #105 — на коротких входах повторение исчезает):
- убрать доупаковку сегментов в текущий чанк (ветка `fitsJoined(current, …)` в основном цикле — удалить);
- одиночный сегмент сверх бюджета — прежняя дорезка по словам (не менять);
- `separators` для склейки перевода — прежние разделители границ исходника (не менять);
- обновить KDoc пункта 2 «Жадная упаковка…» → «каждый сегмент — отдельный чанк» и синхронизировать KDoc `IndicTransOnnxRuntime.translate`/`chunkBudget`.

Побочные эффекты (зафиксировать в KDoc): декудов больше → длинный вход медленнее, но детектор вырождения и ретрай локализуются по предложению, риск цикла снижается.

## Риски / оговорки

- Маска n=3 запрещает и легитимные повторные 3-граммы («no no no…»): фолбэк — ретрай без маски + `uniqueWordRatio` + скидка «повтор из входа» в `isDegenerateOutput` (не удалять).
- Скорость многосоставных входов ниже (несколько декодов вместо одного) — осознанный размен на устойчивость; одиночные предложения (основной случай RU⇄NE через slimt) без изменений по скорости.
- Для 1B-пар (если вернутся из ветки) изменения тоже применимы и безвредны: маска срабатывает только на реально повторяющихся 3-граммах, EOS не маскируется.
