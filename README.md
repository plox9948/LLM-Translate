# LLM-Translate

Офлайн-переводчик для Android (RU ⇄ EN ⇄ NE). Весь инференс выполняется на устройстве —
приложение не требует интернета во время перевода.

## Возможности

- **Перевод текста** между русским, английским и непальским через локальные ONNX-модели
  (Marian opus-mt_tiny RU⇄EN, IndicTrans2 для непальского).
- **Распознавание речи** (STT) через sherpa-onnx: Zipformer/GigaAM (ru), Parakeet (en),
  IndicConformer (ne), Whisper Small (мультиязычный).
- **Синтез речи** (TTS) через системный Android TextToSpeech
  (с поддержкой RHVoice / eSpeak NG как альтернативных движков).
- **Менеджер моделей**: каталог моделей, скачивание с докачкой (Range),
  проверка SHA-256, импорт своих файлов моделей через SAF, экспорт моделей.
- **Управление памятью**: в ОЗУ только активные модели, выгрузка при сворачивании
  приложения, предупреждения о нехватке ОЗУ/места.

## Стек

- Kotlin, Jetpack Compose + Material 3
- MVVM + Clean Architecture (data / domain / ui)
- Hilt (DI), Coroutines + Flow
- Room (метаданные моделей), DataStore (выбор), WorkManager (скачивание)
- ONNX Runtime (перевод), sherpa-onnx (STT) — inference AAR, без нативной сборки с нуля
  (библиотека STT вендорится патченой — см. «Вендореные нативные библиотеки»)

## Сборка

### Требования

- Android Studio (или JDK 17 + Android SDK 34)

### Шаги

1. Клонировать репозиторий:

   ```bash
   git clone http://31.44.89.204:3000/plox/LLM-Translate.git
   cd LLM-Translate
   ```

2. Создать `local.properties` с указанием пути к Android SDK:

   ```
   sdk.dir=/path/to/android/sdk
   ```

3. Собрать:

   ```bash
   ./gradlew assembleDebug
   ```

4. Установить на устройство:

   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

## Вендореные нативные библиотеки

В `app/src/main/jniLibs/<abi>/libsherpa-onnx-jni.so` лежит патченая копия библиотеки
из AAR sherpa-onnx. AAR собран против ONNX Runtime 1.28.2 и требует строго
versioned-символ `OrtGetApiBase@VERS_1.28.2`, тогда как в APK попадает
`libonnxruntime.so` 1.30.0 от onnxruntime-android (узел `VERS_1.30.0`) — без патча
STT падает при инициализации `OfflineRecognizer` (`UnsatisfiedLinkError`).
Патч переименовывает version-node в `VERS_1.30.0` (строки одинаковой длины —
побайтовая замена без сдвига таблиц, с пересчётом `vna_hash`, по которому
Android-линкер сопоставляет версии); локальные jniLibs имеют приоритет при слиянии,
`pickFirst` подавляет дубликат из AAR.

**Обязательное правило:** после обновления `sherpa-onnx` или `onnxruntime-android`
в `gradle/libs.versions.toml` перегенерировать библиотеки скриптом:

```powershell
tools/patch-sherpa-jni-ort-version.ps1 -AarExtractDir <папка с распакованным AAR sherpa-onnx>
```

Ожидаемая структура входа: `<AarExtractDir>/jni/<abi>/libsherpa-onnx-jni.so`.
По умолчанию патчатся ABI `arm64-v8a, x86_64` и версия `VERS_1.28.2 → VERS_1.30.0`
(переопределяются параметрами `-Abis`, `-FromVersion`, `-ToVersion`; при обновлении
ORT их нужно выставить актуальными). Результат — в `app/src/main/jniLibs/<abi>/`.

Скрипт идемпотентен (патчит всегда из распакованного AAR, бросает ошибку на уже
патченом входе). Когда апстрим sherpa-onnx соберёт AAR с ORT >= 1.30, патч можно убрать:
удалить `app/src/main/jniLibs/`, pickFirst для `libsherpa-onnx-jni.so` и скрипт.

## Жизненный цикл моделей

Модели (ONNX-сессии перевода и STT) живут только в ОЗУ процесса и загружаются
**лениво** — приложения держит в памяти лишь те модели, которые реально используются.

### Запуск приложения

При старте тяжёлые модели **не загружаются**. Выполняется только обслуживание:

- прогрев кэша языка интерфейса;
- очистка записей Room с устаревшими runtime-типами;
- удаление файлов моделей, отсутствующих в каталоге.

Инициализируется лишь движок TTS (системный TextToSpeech / RHVoice / eSpeak) —
это отдельный системный сервис, память процесса приложения он не расходует.

Первая загрузка модели в ОЗУ происходит при первом действии пользователя:

- **модель(и) перевода** — по нажатию «Перевести»: выбирается цепочка моделей для
  направления (при отсутствии прямой — через английский) и загружается каждая модель
  цепочки, которую ещё нет в памяти;
- **STT-модель** — по первому распознаванию (активная модель, выбранная на экране
  «Модели»); whisper при смене языка пересобирает распознаватель.

### Сворачивание приложения

По сворачивании (все активности остановлены — Home, переход в другое приложение)
срабатывает `ON_STOP` процесса: **все рантаймы выгружаются из ОЗУ** — сессии ONNX
перевода (Marian, IndicTrans) и распознаватель sherpa. Выгрузка асинхронная (не
блокирует UI) и синхронизирована с инференсом: если перевод/распознавание ещё идёт,
выгрузка **ждёт его окончания** (инференс может занимать десятки секунд) — сессии
не закрываются посреди работы.

При возврате в приложение модели **не перезагружаются автоматически** — они будут
загружены заново при следующем «Перевести» / распознавании (первое действие после
возврата занимает время загрузки модели).

### Закрытие приложения

При нормальном закрытии перед завершением процесса также выполняется `ON_STOP` и
выгрузка рантаймов. Если ОС убивает процесс (свайп из недавних, нехватка памяти) —
вся память процесса освобождается системой. Никакого состояния моделей на диске нет:
метаданные хранятся в Room, выбор — в DataStore, файлы моделей не затрагиваются.

> 💡 Управление памятью остаётся предсказуемым: до запуска — ~145 МБ, при переводе —
> дельта загруженной модели (см. таблицу RAM выше), после сворачивания — память
> освобождается. Часть ONNX-арен может возвращаться ОС с задержкой (см. примечания
> к таблице).

## Фактическое потребление RAM (измерено на реальном устройстве)

Замеры выполнены на телефоне OnePlus (Android 9, 5738 МБ ОЗУ): инструментационный
тест `ModelRamProfileTest` загружает модель и выполняет инференс, а скрипт
`tools/ramprof.sh` периодически снимает PSS процесса через `dumpsys meminfo`.
Baseline пустого приложения — около **145 МБ**; в таблице указана дельта PSS к нему.

| Модель | Steady RAM | Пик RAM | После выгрузки |
|--------|-----------|---------|----------------|
| Opus-MT Tiny RU→EN (int8) | ~210 МБ | ~400 МБ | освобождается полностью |
| Opus-MT Tiny EN→RU (int8) | ~210 МБ | ~430 МБ | освобождается полностью |
| IndicTrans2 indic→EN (int8) | ~340 МБ | ~420 МБ | остаток ~240 МБ (арены ONNX) |
| IndicTrans2 EN→indic (int8) | ~435 МБ | ~520 МБ | освобождается полностью |
| Zipformer RU int8 | ~110…205 МБ | ~275 МБ | частичный остаток |
| Zipformer RU fp32 (выбирается при fp32-файлах в каталоге) | ~315…405 МБ | ~675 МБ | остаток ~230 МБ |
| GigaAM v2 CTC RU | ~277 МБ | ~280 МБ | остаток ~150 МБ |
| Parakeet 110M EN | ~220 МБ | ~220 МБ | освобождается полностью |
| IndicConformer NE | ~243 МБ | ~245 МБ | освобождается (до ~2 с) |
| Whisper Small Multilingual | ~455 МБ | ~1050 МБ при первой смене языка | освобождается полностью |

Примечания:

- TTS выполняется в отдельном процессе движка синтеза речи системы — на синтез
  приложение память модели не расходует.
- «Пик» включает кратковременные аллокации при инициализации и инференсе (оптимизация
  графа ONNX, буферы декодирования).
- Для Whisper первая смена языка пересоздаёт распознаватель: в момент пересборки
  в памяти находятся оба экземпляра (пик ~1,05 ГБ). На устройствах с 4 ГБ ОЗУ
  для распознавания лучше использовать Zipformer/GigaAM, Whisper — при 6 ГБ.
- Zipformer: если в каталоге модели лежат и fp32-, и int8-файлы, приложение может
  выбрать fp32 (порядок файлов не детерминирован) — RAM выше в 2–3 раза.

> 💡 **Рекомендуемая RAM устройства**: для перевода — от 3 ГБ, для Whisper STT — 6 ГБ,
> для остальных STT-моделей — от 2 ГБ.

## Резервное копирование и перенос на другое устройство

Приложение умеет экспортировать все модели и настройки в ZIP-архив и восстанавливать их.

### Экспорт на телефоне

1. Откройте экран «Модели».
2. Нажмите **«Бэкап»** — выберите место сохранения.
3. Получите файл вида `llm_translate_backup_<timestamp>.zip`.

### Импорт на телефоне

1. Скопируйте архив на телефон (по USB, облаку, Bluetooth и т.д.).
2. Откройте экран «Модели» → **«Восстановить»**.
3. Выберите архив. Модели и настройки будут восстановлены.

### Подготовка архива на ПК

Если нужно передать модели с ПК на телефон (или наоборот), создайте архив вручную.

**Структура архива:**

```
llm_translate_backup.zip
├── manifest.json          # метаданные моделей (обязательно)
├── settings.json          # настройки (опционально)
└── models/                # файлы моделей
    ├── MARIAN_ONNX/
    │   └── opus-mt-tiny-ru-en-int8-v2/
    │       ├── encoder_model.onnx
    │       └── decoder_model.onnx
    └── SHERPA/
        └── stt-ru-zipformer-2024-09-18/
            ├── encoder.int8.onnx
            ├── decoder.int8.onnx
            └── joiner.int8.onnx
```

**manifest.json** — список моделей с путями:

```json
{
  "version": 1,
  "exportedAt": 1700000000000,
  "models": [
    {
      "id": "opus-mt-tiny-ru-en-int8-v2",
      "category": "TRANSLATION",
      "displayName": "Opus-MT Tiny (RU→EN, int8)",
      "description": "Marian MT opus-mt_tiny int8",
      "runtime": "MARIAN_ONNX",
      "sizeBytes": 112367622,
      "ramRequiredMb": 1500,
      "languages": ["ru", "en"],
      "quality": 4,
      "speed": 5,
      "url": "",
      "urls": [],
      "sha256": null,
      "license": "Apache-2.0",
      "minAndroidSdk": 26,
      "recommendedRamMb": 3072,
      "relativePath": "models/MARIAN_ONNX/opus-mt-tiny-ru-en-int8-v2/encoder_model.onnx",
      "isBuiltin": true
    }
  ]
}
```

**settings.json** — активные модели и настройки:

```json
{
  "activeTranslation": "opus-mt-tiny-ru-en-int8-v2",
  "activeStt": "stt-ru-zipformer-2024-09-18",
  "activeTts": "tts-system",
  "ttsEngine": "system",
  "uiLanguage": "ru",
  "theme": "dark"
}
```

**Пошагово:**

1. Скачайте нужные модели (ONNX-каталоги, sherpa-модели).
2. Создайте папку `models/` с подкаталогами runtime (`MARIAN_ONNX`, `INDICTRANS_ONNX`, `SHERPA`).
3. Разместите файлы моделей.
4. Создайте `manifest.json` с записью на каждую модель (поле `relativePath` — путь к файлу внутри архива).
5. При желании создайте `settings.json`.
6. Заархивируйте всё в ZIP.
7. На телефоне: «Модели» → «Восстановить» → выберите архив.

> 💡 Проще всего: сделать «Бэкап» на одном телефоне и восстановить на другом.
