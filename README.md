# LLM-Translate

Офлайн-переводчик для Android (RU ⇄ EN ⇄ NE). Весь инференс выполняется на устройстве —
приложение не требует интернета во время перевода.

📖 **Инструкция для пользователей** (установка, первый запуск, модели, частые
вопросы): [русская](USER_GUIDE.md) / [English](USER_GUIDE.en.md).

## Возможности

- **Перевод текста** между русским, английским и непальским через локальные модели
  (языковые паки Firefox Translations / Bergamot RU⇄EN, IndicTrans2 для непальского).
  В результате перевода сохраняются переносы строк исходника (абзацы и
  многострочное оформление). Результат привязан к направлению: при его смене
  карточка результата скрывается, озвучивание чужим языком исключено (issue #59).
- **Распознавание речи** (STT) через sherpa-onnx: GigaAM v3 (ru), Parakeet (en),
  IndicConformer (ne), Whisper Small (мультиязычный, временно скрыт из каталога
  в UI — issue #55). Недошедшую STT-модель исходного языка экран «Перевод»
  предлагает скачать прямо в памятке недостающих моделей (issue #56).
- **Синтез речи** (TTS): по умолчанию — системный Android TextToSpeech; для
  каждого языка язык озвучивания можно переключить чипами RU/EN/NE на локальную
  Piper-модель (рус/англ/непал), тап по чипу системной карточки возвращает язык
  на системный движок. При недоступности системного синтеза для языка приложение
  само предлагает и качает Piper-модель языка (issues #50, #53, #57).
  Движки RHVoice / eSpeak NG временно скрыты из интерфейса флагом `hidden`
  в каталоге (issue #55) — ранее сделанный настройкой выбор сохраняется.
- **Менеджер моделей**: каталог моделей, скачивание с защищённой докачкой
  (Range + If-Match/ETag) и проверкой SHA-256 каждого файла, отмена скачивания,
  импорт по карточкам каталога (своих файлов и ZIP-экспортов этой же программы через
  SAF; ZIP с метаданными `model_meta.json` регистрирует модель прямо по карточке)
  и восстановление из ZIP-бэкапа (файлы моделей сверяются с SHA-256 из манифеста архива,
  повреждённые пропускаются), экспорт моделей
  (мультифайловые каталоги упаковкируются в `.zip`).
- **STT по языкам**: глобальной «активной» STT-модели нет — модель назначается
  на каждый язык чипами языков на карточках экрана «Модели» (дефолт для ne —
  IndicConformer); модель перевода выбирается автоматически по направлению,
  «Выбрать» из карточек осталось только у TTS-движков.
- **Отмена операций**: перевод и распознавание речи отменяются кнопкой «Отмена»
  на экране «Перевод»; отменяются скачивание и распаковка моделей.
- **История переводов**: отдельная вкладка; тап по записи истории подставляет
  текст и направление на экран «Перевод» без повторного скачивания модели.
- **Избранное**: звёздочка на результате экрана «Перевод» (для явного направления;
  при AUTO-источник звезда выключена) и на карточках «Истории»; отдельная вкладка
  «Избранное» с озвучиванием оригинала и перевода каждой записи и поиском фраз
  (регистронезависимо по оригиналу и переводу).
- **Онбординг первого запуска**: bottom-sheet выбора направления перевода и карточка
  недостающих моделей текущего направления с кнопкой «Скачать» на каждую модель
  прямо на экране «Перевод» (для уже скачиваемых — прогресс вместо кнопки);
  в карточке отдельной секцией «Распознавание» показывается недостающая STT-модель
  исходного языка (issue #56).
- **Языки интерфейса**: русский, английский, непальский (values-ne) и «по системе»;
  при первом запуске язык UI определяется языком системы (детерминированно
  отображается в один из поддерживаемых), переключается в «Настройках».
- **Обмен направления перевода**: стрелка между языковыми чипами на экране «Перевод»
  меняет направление, а показанный перевод автоматически подставляется в поле ввода —
  удобно проверять перевод в обе стороны без ручного копирования;
- **Копирование перевода** в буфер обмена одной кнопкой на экране «Перевод»;
  вывод IndicTrans2 пост-обрабатывается: подряд идущие дубли перевода и хвостовые
  дубли слов, порождённые декодером, схлопываются в одно вхождение, затем
  убираются лишние пробелы вокруг пунктуации (вывод детокенизируется по
  целевому языку — корректная запись `।`, `.`, скобок).
- **Стабилизация непальского перевода** (issues #61–#63): перед инференсом
  английский вход приводится к формату обучения модели (пробелы вокруг
  пунктуации с защитой чисел, URL, email и инициалов; кавычки/тире — для обоих
  исходников), на вход энкодера подаётся завершающий `</s>`; неизвестные токены
  кодируются `<unk>`, а не `<s>`. Если декодер всё же зациклился (хвостовой
  повтор слов, упор в лимит длины) — выполняется один автоматический повторный
  проход с запретом повторяющихся 3-грамм; если и он вырожден — приложение
  возвращает явную ошибку вместо «мусорного» текста. Длинные тексты (в т.ч.
  непальские с дандой `।` без пробелов) режутся по границам предложений и
  укладываются в лимит позиционных эмбеддингов модели (258 токенов) с
  сохранением переносов строк — перевод абзацев, раньше падал с ошибкой
  инференса, теперь доходит до конца.
- **Управление памятью**: в ОЗУ только активные модели, выгрузка при сворачивании
  приложения (настраиваемый тайм-аут), политика при смене направления — **keep**
  (по умолчанию, движки держат модели в LRU-кэше) или **unload** (в ОЗУ только
  текущая модель); при удалении модели она сразу выгружается из движков; карточка
  загруженных в ОЗУ моделей с PSS процесса и оценкой потребления (в ней видны и
  загруженные Piper TTS-сессии — issue #52), выбор TTS-движка, предупреждения
  о нехватке ОЗУ/места.

## Стек

- Kotlin, Jetpack Compose + Material 3
- MVVM + Clean Architecture (data / domain / ui)
- Hilt (DI), Coroutines + Flow
- Room (метаданные моделей), DataStore (выбор), WorkManager (скачивание)
- ONNX Runtime (перевод IndicTrans2), sherpa-onnx (STT) — inference AAR
  (библиотека STT вендорится патченой — см. «Вендореные нативные библиотеки»)
- Нативный слой: C++-движок slimt (Bergamot / Firefox Translations, RU⇄EN) —
  git submodule `app/third_party/slimt`, сборка NDK + CMake, JNI-мост `app/src/main/cpp`

## Сборка

Готовые APK релизов публикуются в **[GitHub Releases](https://github.com/plox9948/LLM-Translate/releases)**
(начиная с v0.5.7 — подписанные release-сборки, см. «Подписанные релизы»),
собирать из исходников не обязательно.

### Требования

- Android Studio (или JDK 17 + Android SDK 34)

### Шаги

1. Клонировать репозиторий:

   ```bash
   git clone --recursive https://github.com/plox9948/LLM-Translate.git
   cd LLM-Translate
   ```

   `--recursive` обязателен: движок slimt подключён как git submodule
   (`app/third_party/slimt`); без него CMake-сборка нативной библиотеки не соберётся.
   Если клонирование уже сделано без ключа — `git submodule update --init --recursive`.

2. Создать `local.properties` с указанием пути к Android SDK:

   ```
   sdk.dir=/path/to/android/sdk
   ```

3. Собрать:

   ```bash
   ./gradlew assembleDebug
   ```

4. Установить на устройство:

   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

### Подписанные релизы (APK по ссылке)

Публичные APK — **release-сборки, подписанные релизным ключом** (не debug):
обновления поверх установленной версии ставятся только той же подписью, а
minified-сборка R8 быстрее debug. Ключ и пароли в git не попадают:

- keystore: `keystore/release.keystore` (в `.gitignore`) — **обязателен к резервной
  копии**: при его утере знакомые не смогут ставить обновления поверх
  установленных версий (понадобится удаление с потерей истории/избранного);
- пароли (`RELEASE_STORE_FILE`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`,
  `RELEASE_KEY_PASSWORD`) — в некоммитируемом `local.properties`.

Создание keystore с нуля (однократно, на машине релизов):

```powershell
keytool -genkeypair -v -keystore keystore\release.keystore -alias llmtranslate `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -dname "CN=LLM-Translate, OU=dev, O=plox, C=US"
```

Сборка подписанного релиза: `./gradlew assembleRelease` →
`app/build/outputs/apk/release/app-release.apk`; если `RELEASE_STORE_*` не заданы,
задачи релизного контура (`assembleRelease`, `bundleRelease`, `installRelease`)
падают с понятной ошибкой непосредственно перед сборкой APK. Проверка подписи:
`apksigner verify --print-certs app-release.apk` (SHA-256 отпечаток ключа —
`067485da0986b64792f3d949b457f65498ec4214538627c3ca1925da0d098240`).

Релизные ключи нужны только релизному контуру: `assembleDebug`, unit- и
instrumentation-тесты и прочие задачи собираются и запускаются без заданных
`RELEASE_STORE_*` (конфиг подписи создаётся лениво, issue #66).

**Правило R8:** C++-части onnxruntime/sherpa/slimt ищут классы и поля по исходным
именам (`FindClass`/`GetFieldID`) — любые новые JNI-библиотеки требуют keep-правил
в `app/proguard-rules.pro` (см. `ai.onnxruntime.**`, `com.k2fsa.sherpa.onnx.**`);
release-APK обязательно прогоняется на устройстве (инференс, STT, бэкап/импорт) —
ошибки R8 проявляются только в рантайме.

## Вендореные нативные библиотеки

В `app/src/main/jniLibs/<abi>/libsherpa-onnx-jni.so` лежит патченая копия библиотеки
из AAR sherpa-onnx. AAR собран против ONNX Runtime 1.28.2 и требует строго
versioned-символ `OrtGetApiBase@VERS_1.28.2`, тогда как в APK попадает
`libonnxruntime.so` 1.30.0 от onnxruntime-android (узел `VERS_1.30.0`) — без патча
STT падает при инициализации `OfflineRecognizer` (`UnsatisfiedLinkError`).
Патч переименовывает version-node в `VERS_1.30.0` (строки одинаковой длины —
побайтовая замена без сдвига таблиц, с пересчётом `vna_hash`, по которому
Android-линкер сопоставляет версии); локальные jniLibs имеют приоритет при слиянии,
`pickFirst` подавляет дубликат из AAR.

**Обязательное правило:** после обновления `sherpa-onnx` или `onnxruntime-android`
в `gradle/libs.versions.toml` перегенерировать библиотеки скриптом:

```powershell
tools/patch-sherpa-jni-ort-version.ps1 -AarExtractDir <папка с распакованным AAR sherpa-onnx>
```

Ожидаемая структура входа: `<AarExtractDir>/jni/<abi>/libsherpa-onnx-jni.so`.
По умолчанию патчатся ABI `arm64-v8a, x86_64` и версия `VERS_1.28.2 → VERS_1.30.0`
(переопределяются параметрами `-Abis`, `-FromVersion`, `-ToVersion`; при обновлении
ORT их нужно выставить актуальными). Результат — в `app/src/main/jniLibs/<abi>/`.

Скрипт идемпотентен (патчит всегда из распакованного AAR, бросает ошибку на уже
патченом входе). Когда апстрим sherpa-onnx соберёт AAR с ORT >= 1.30, патч можно убрать:
удалить `app/src/main/jniLibs/`, pickFirst для `libsherpa-onnx-jni.so` и скрипт.

## Жизненный цикл моделей

Модели (движки перевода slimt/ONNX и STT-сессии) живут только в ОЗУ процесса и загружаются
**лениво** — приложения держит в памяти лишь те модели, которые реально используются.

### Запуск приложения

При старте тяжёлые модели **не загружаются**. Выполняется только обслуживание:

- прогрев кэша языка интерфейса;
- очистка записей Room с устаревшими runtime-типами;
- удаление файлов моделей, отсутствующих в каталоге;
- удаление остатков WAV-записей распознавания (обычно файл удаляется сразу после
  распознавания, остатки от убитого процесса убираются при старте).

Инициализируется лишь системный движок TTS (TextToSpeech / RHVoice / eSpeak) —
это отдельный системный сервис, память процесса приложения он не расходует;
Piper TTS-сессии лениво загружаются в процесс при первом озвучивании назначенным
языку голосом и отображаются в блоке «Загружено в память»; при удалении или
перескачивании Piper-модели её сессия закрывается немедленно (в блоке не остается
«призрака», следующее озвучивание читает новые файлы).

Первая загрузка модели в ОЗУ происходит при первом действии пользователя:

- **модель(и) перевода** — по нажатию «Перевести»: выбирается цепочка моделей для
  направления (при отсутствии прямой — через английский) и загружается каждая модель
  цепочки, которую ещё нет в памяти;
- **STT-модель** — по первому распознаванию: выбирается по языку источника —
  сначала модель, назначенная этому языку чипами на карточке «Модели», для ne
  по умолчанию IndicConformer, иначе первая подходящая; в режиме AUTO —
  мультаязычная (приоритет у Whisper); whisper при смене языка пересобирает
  распознаватель.

### Смена направления и удаление моделей (политика keep/unload)

В «Настройках» есть политика удержания моделей при смене направления:

- **keep** (по умолчанию) — движки перевода (slimt) и STT (sherpa) держат загруженные
  пучки моделей во внутреннем **LRU-кэше**: выбор ранее использованной модели
  не выполняет загрузку заново (быстрый путь из кэша);
- **unload** — движок держит в ОЗУ только текущую модель: чужие пучки выгружаются
  при каждой загрузке новой.

При **удалении модели** её нативный handle немедленно изымается из кэша движков
(`releaseModel`): без этого повторная загрузка того же id взяла бы из кэша handle
по уже удалённым файлам. Выгрузка выполняется под мьютексом движка с ожиданием
окончания активного инференса — use-after-free исключён.

### Сворачивание приложения

По сворачивании (все активности остановлены — Home, переход в другое приложение)
срабатывает `ON_STOP` процесса, и `BackgroundUnloadScheduler` планирует выгрузку
**всех рантаймов** из ОЗУ — движков перевода (slimt, IndicTrans) и распознавателя
sherpa — по таймауту фонового простоя. Таймаут по умолчанию — **5 минут**
(настраивается в «Настройках»: сразу, через 15 минут, не выгружать); при возврате
в foreground до истечения таймаута выгрузка отменяется и рантаймы остаются в ОЗУ.
Выгрузка асинхронная (не блокирует UI) и синхронизирована с инференсом: если
перевод/распознавание ещё идёт, выгрузка **ждёт его окончания** (инференс может
занимать десятки секунд) — сессии не закрываются посреди работы.

При возврате в приложение **после состоявшейся выгрузки** модели **не перезагружаются
автоматически** — они будут загружены заново при следующем «Перевести» / распознавании
(первое действие после возврата занимает время загрузки модели).

### Закрытие приложения

При нормальном закрытии (в том числе свайпе из недавних) процесс завершается и вся
его память освобождается системой. Никакого состояния моделей на диске нет:
метаданные хранятся в Room, выбор — в DataStore, файлы моделей не затрагиваются.

Память моделей не остаётся и когда процесс живёт в фоне: после сворачивания
`BackgroundUnloadScheduler` выгружает рантаймы по таймауту. Измерено на устройстве
(IndicTrans2 EN→NE): после перевода процесс занимал ~535 МБ, через **80 с** —
~174 МБ, через 2 мин — ~119 МБ, то есть **ниже baseline пустого приложения
(~126 МБ)** — память реально возвращается ОС. Остаток в десятки МБ наблюдается
только при принудительном `release()` внутри живого процесса — тест-раннера
`ModelRamProfileTest` (см. примечания к таблице RAM); исключение — slimt EN→RU.

> 💡 Управление памятью остаётся предсказуемым: пустое реальное приложение —
> ~126 МБ, при переводе — дельта загруженной модели (см. таблицу RAM ниже), после
> сворачивания рантаймы выгружаются по таймауту `BackgroundUnloadScheduler` и память
> возвращается ОС (возврат арен ONNX/sherpa может запаздывать на 10–26 с — см.
> примечания к таблице).

## Загрузка и целостность моделей

- SHA-256 зафиксированы для **всех файлов всех моделей каталога**: в `models/manifest.json`
  (единственный источник хешей) и в `app/src/main/assets/models_catalog.json` — в полях
  `sha256` (однофайловые модели) и `sha256s` (массив хешей по индексам `urls`). Версии
  манифеста и каталога синхронизированы — синхронность контролируется unit-тестом
  (issue #68).
- При установке проверяется хеш **каждого** скачанного файла. При несовпадении после
  докачки часть отбрасывается и скачивание автоматически повторяется с нуля; несовпадение
  после свежей загрузки — неустранимая ошибка с понятным текстом.
- Докачка защищена от перезаливании файлов на сервере: рядом с `.part` сохраняются ETag и
  полный размер, возобновление идёт `Range + If-Match`; при несовпадении `Content-Range`,
  ответе 200 вместо 206 или отсутствии метаданных часть отбрасывается. Для слабых
  ETag (`W/...`) If-Match не отправляется (RFC), целостность держится на SHA-256.
- Отмена скачивания удаляет осиротевшие `.part`/`.part.meta` и недокачанные архивы;
  отмена распаковки удаляет файлы этой распаковки, сам архив и каталог модели,
  созданный при распаковке архивной установки — осиротевшие каталоги прерванных
  архивных установок не накапливаются (issue #66; zip-slip-защита на месте).
- При повторной попытке установки (retry WorkManager) **уже скачанные файлы пакета не
  перекачиваются**: они пересверяются по SHA-256 на диске и пропускаются, мусор докачки
  рядом с целым файлом удаляется. Раскладка каталога цели (`models/<RUNTIME>/<id>`)
  рассчитана один раз в `DownloadLayout` — по той же раскладке чистятся остатки
  прерванных установок, включая целевые файлы, переименованные до остановки
  установки.
- Открытый HTTP-трафик разрешён только хостам загрузки встроенного каталога
  (github.com, huggingface.co, storage.googleapis.com — сами URL идут по https,
  разрешение на случай http-зеркал) и loopback-адресам (фикстуры
  instrumentation-тестов инсталляторов); остальной трафик — HTTPS-only
  (`res/xml/network_security_config.xml`).
- Языковые паки Firefox Translations (Bergamot) CDN Mozilla отдаёт сжатыми gzip: SHA-256
  проверяется по байтам `.gz`-архива, после чего инсталлятор распаковывает (gunzip) файл
  и удаляет архив — на диске в каталоге модели лежат `*.bin`/`*.spm` без `.gz`.
- Локальный набор моделей для сети не обязателен: `scripts/download_models.ps1` / `.sh`
  качают модели в `models/<id>/` с проверкой хешей манифеста.

## Отмена длительных операций

- **Перевод и распознавание** — кнопка «Отмена» на экране «Перевод»: прерывает greedy-генерацию
  и STT, состояние возвращается в idle без ошибки; перевод и распознавание используют один общий Job
  и не выполняются параллельно.
- **Загрузка моделей** — «Отменить» на экране «Модели»: воркер WorkManager прерывается
  немедленно (циклы чтения/распаковки проверяют отмену), файлы чистятся.
- **Загрузка модели в ОЗУ** (создание ONNX-сессий) — отмена действует на границах фаз:
  нативные шаги ONNX/sherpa/slimt (создание сессии, один шаг декода) прервать нельзя, отмена
  сработает сразу после них.

## Обработка ошибок и устойчивость

- **Локализованные сообщения об ошибках** (issue #65): сбои перевода, распознавания,
  записи с микрофона, операций истории/избранного и бэкапа показываются единообразно
  текстами из строк интерфейса на языке UI (русский, английский, непальский), включая
  сообщения при неудачном удалении записей и добавлении в избранное на экранах
  «История» и «Избранное».
- **Устойчивые подписки Истории/Избранного** (issue #67): при исключении в Room
  подписка на список автоматически перезапускается — приложение не падает, показывается
  сообщение («Не удалось загрузить историю» / «Не удалось загрузить избранное»), а
  список восстанавливается сам, как только база снова отвечает.
- **Явная ошибка вместо порчи перевода** (issue #64): если в заголовке slimt-пака
  (`.bin`) не распознана конфигурация модели (число слоёв по именам тензоров), её
  загрузка завершается явной ошибкой, а не молчаливым переводом с архитектурой
  пресета — повреждённая или несовместимая модель не выдаёт бессмысленный текст.
- **Атомарная подмена файлов при импорте бэкапа** (issue #66): новое содержимое
  модели сначала копируется во временный путь рядом с целью, и прежний файл
  удаляется и подменяется только после успешного копирования — при сбое копирования
  ранее установленная модель остаётся нетронутой.
- **Запись с микрофона: таймер и авто-остановка** (issue #68): в индикаторе
  записи показывается счётчик длительности; по жёсткому потолку **3 минуты**
  запись останавливается сама и распознание выполняется как обычно (защита от
  «забыл выключить»). Аудио стримится во временный WAV-файл — память записи больше
  не растёт с её длительностью.
- **Модель не остаётся «старой» после замены** (issues #69, #70): при повторном
  ZIP-импорте той же модели и при восстановлении из бэкапа кэш движков отпускает
  старый handle до перезаписи/подмены файлов — после замены перевод сразу идёт
  по новым файлам, без перезапуска приложения. При замещающем импорте каталог
  предыдущей версии модели удаляется с диска (осиротевшие файлы не копятся),
  а прерванная подмена не портит ранее установленную модель (совместно с
  атомарной подменой issue #66).

## Фактическое потребление RAM (измерено на реальном устройстве)

Замеры пересняты на телефоне OnePlus A3003 (Android 9, 5738 МБ ОЗУ) на сборке
v0.4.1+ (issue #32): инструментационный тест `ModelRamProfileTest#ramProfile`
загружает модель, выполняет инференс и удерживает состояние (`-e hold 15000`,
`-e hold2 32000`), а параллельно на устройстве скрипт `tools/ramprof.sh` с шагом
~0.5 с снимает суммарный PSS процесса — `dumpsys meminfo` TOTAL.

Разделяют два baseline: **пустое реальное приложение — ~126 МБ**; base тестового
процесса (`com.plox.llmtranslate.test`) — **~147 МБ** (в одном прогоне — 151 МБ).
В таблице — абсолютный PSS тест-процесса, в скобках относительно него дельта;
в колонке «После выгрузки» — остаток после `release()`.

| Модель | Steady RAM | Пик RAM | После выгрузки |
|--------|-----------|---------|----------------|
| Firefox Translations EN→RU (Bergamot/slimt) | 289 МБ (+142) | 290 МБ | 238 МБ (**+92 ⚠**) |
| Firefox Translations RU→EN (Bergamot/slimt) | 232 МБ (+85) | 233 МБ | 150 МБ (+3) |
| IndicTrans2 indic→EN (int8) | 475 МБ (+328) | 549 МБ | 167 МБ (+20) |
| IndicTrans2 EN→indic (int8) | 569 МБ (+422) | 659 МБ | 167 МБ (+20) |
| GigaAM v3 E2E CTC RU | 419 МБ (+272) | 420 МБ | 167 МБ (+20) |
| Parakeet 110M EN | 358 МБ (+211) | 360 МБ | 167 МБ (+20) |
| IndicConformer NE | 388 МБ (+241) | 410 МБ | 168 МБ (+21) |
| Whisper Small Multilingual | 912 МБ (+765) | 928 МБ | 168 МБ (+21) |

Примечания:

- Системный TTS выполняется в отдельном процессе движка синтеза речи системы —
  на него приложение память модели не расходует. Piper TTS работает в процессе
  приложения (сессии sherpa-onnx), его загрузка видна в блоке «Загружено
  в память» (оценка по каталогу), в таблице RAM не измерялась.
- «Пик» включает кратковременные аллокации при инициализации и инференсе (оптимизация
  графа ONNX, буферы декодирования).
- «После выгрузки» измеряется через 30 с после `release()` в живом тест-процессе.
  У ONNX/sherpa-моделей остаётся ~17–21 МБ — кучи `malloc` onnxruntime и
  sherpa-onnx; их освобождение ОС может запаздывать на 10–26 с после `release()`
  (замер на 30-й секунде фиксирует ещё не полностью освобождённый остаток).
  У slimt RU→EN остаток практически нулевой (+3 МБ).
- ⚠ slimt EN→RU: после выгрузки остаётся ~92 МБ — mmap-страницы int8-модели
  не возвращаются ОС до смерти процесса. Наблюдение ограничено тест-процессом,
  требует отдельного исследования.
- Whisper: пик при смене языка (пересоздание распознавателем) в текущей серии
  не переснимался — тест выполняет один transcribe; steady +765 МБ, пик в рамках
  одного распознавания ~928 МБ. На устройствах с 4 ГБ ОЗУ для распознавания лучше
  использовать GigaAM, Whisper — при 6 ГБ.
- slimt (Bergamot): файл модели отображается в память через **mmap**, поэтому
  `Debug.MemoryInfo` в `ModelRamProfileTest` показывает дельту 0 (mmap-страницы
  в него не входят). Честные числа даёт только **TOTAL PSS из `dumpsys meminfo`
  после инференса**: страницы модели прогреваются при переводе, поэтому RSS
  растёт в процессе перевода, а не при загрузке сессии.
- Цепочка NE→RU (одновременно slimt RU→EN + IndicTrans2 EN→Indic) — суммарная
  дельта обеих моделей (~+85 и ~+422 МБ к base процесса, всего ~+510 МБ);
  при составных направлениях складываются дельты всех моделей цепочки.

> 💡 **Рекомендуемая RAM устройства**: для прямого перевода RU⇄EN (Firefox Translations)
> достаточно 2 ГБ; для перевода с непальским (IndicTrans2) — от 4 ГБ, цепочки с
> непальским (две модели перевода одновременно) — 3–4 ГБ; для Whisper STT — 6 ГБ,
> для остальных STT-моделей — от 2 ГБ.

## Известные ограничения качества перевода

- **Непальский ⇄ английский (IndicTrans2, 200M int8)**: при обратном переводе
  временные оттенки могут нейтрально смещаться — например «на 3 часа позже»
  в непальский даёт `तीन घण्टा पछि`, а непальское `पछि` покрывает и «later»,
  и «after», поэтому обратно получается «через 3 часа». Это лексическое
  ограничение модели, а не дефект приложения; смысл предложения сохраняется.
  Точность чисел и имён в длинных текстах также ограничена размером 200M-модели.
- Для направлений EN→NE/NE→EN используется одна и та же модель IndicTrans2
  int8 — замены модели и более тяжёлые варианты не применяются.

## Резервное копирование и перенос на другое устройство

Приложение умеет экспортировать все модели и настройки в ZIP-архив и восстанавливать их.

### Экспорт на телефоне

1. Откройте экран «Модели».
2. Нажмите **«Бэкап»** — выберите место сохранения.
3. Получите файл вида `llm_translate_backup_<timestamp>.zip`.

### Импорт на телефоне

1. Скопируйте архив на телефон (по USB, облаку, Bluetooth и т.д.).
2. Откройте экран «Модели» → **«Восстановить»**.
3. Выберите архив. Модели и настройки будут восстановлены. Файлы моделей
   сверяются с контрольными суммами из `manifest.json` — повреждённые записи
   пропускаются (модель можно докачать или импортировать отдельно).

### Экспорт и импорт отдельной модели

- Карточка установленной модели → **«Экспорт»**: одиночный файл модели
  выписывается как есть (`*.onnx` и т.п.), каталог мультифайловой модели
  упаковывается в **`.zip`** — первой записью в него кладутся метаданные
  `model_meta.json` (id, категория, runtime, языки и пр.).
- Карточка каталога (модель ещё не скачана) → **«Импорт»**: выберите ZIP-экспорт
  этой же модели (или одиночный файл) — модель развернётся по каталожной
  раскладке `models/<RUNTIME>/<id>` и станет готова **без скачивания**,
  карточка совпадёт с каталожной (параметры берутся из `model_meta.json`).
  На время экспорта кнопки «Экспорт»/«Удалить» этой карточки блокируются,
  чтобы архив не обрезался.

**settings.json** — настройки (все поля опциональны; в старых архивах
отсутствующие поля при восстановлении не меняются):

```json
{
  "activeTranslation": "firefox-bergamot-ru-en",
  "ttsEngine": "system",
  "uiLanguage": "ru",
  "theme": "dark",
  "sttByLanguage": { "ru": "stt-ru-gigaam-v3-e2e-ctc" },
  "ttsByLanguage": { "ru": "tts-ru-piper-ruslan", "en": "system" },
  "unloadTimeoutMinutes": 5,
  "modelDirectionRetention": "keep",
  "lastSourceLang": "ru",
  "lastTargetLang": "en"
}
```

Восстановление применяет поязыковые назначения STT/TTS, тайм-аут выгрузки,
политику удержания моделей и последнее направление перевода;
`"system"` в `ttsByLanguage` — возврат языка на системный движок синтеза.

**Пошагово:**

1. Скачайте нужные модели (пачки Bergamot из каталога, ONNX-модели IndicTrans, sherpa-модели).
2. Создайте папку `models/` с подкаталогами runtime (`MARIAN_SLIMT`, `INDICTRANS_ONNX`, `SHERPA`).
3. Разместите файлы моделей.
4. Создайте `manifest.json` с записью на каждую модель (поле `relativePath` — путь к файлу внутри архива).
5. При желании создайте `settings.json`.
6. Заархивируйте всё в ZIP.
7. На телефоне: «Модели» → «Восстановить» → выберите архив.

> 💡 Проще всего: сделать «Бэкап» на одном телефоне и восстановить на другом.
